# 手绘图形控件评估与封装方案

## 一、摘要

本方案针对项目 Frontend 中散落的手绘 `ImDrawList` 图形代码，做两件事：

1. **开源替代评估**：逐项判断现有手绘图形能否用成熟开源 ImGui 控件库替换。
2. **控件封装设计**：对「无合适开源替代」的图形，设计成**语义明确、可复用的独立控件模块**（仿 imgui-knobs 的形态：单一用途的命名空间 + 立即模式函数），而不是继续堆在用途过宽的 `UI::` helper 里。

**交付物**：本评估报告 + 设计方案（不含代码实现，实现阶段见文末「可选后续」）。

> 结论速览：
> - 趋势折线图、开关**已用**开源（ImPlot、imgui_toggle），无需再动。
> - 圆形仪表盘**可新增** imgui-knobs 作视觉参考，但其语义是「编辑旋钮」，与「读显式仪表」不完全匹配，**推荐自封装**为 `RadialGauge`。
> - 分段控件、状态徽章、信息卡、地形装饰图**无合适开源**，推荐自封装为独立控件。
> - `CenteredText / DrawRoundedRect / DrawRing / DrawGaugeArc` 属**纯绘制原语**，不属于「控件」，保留在 `UIHelpers` 即可。

## 三、开源替代评估

按「是否值得引入第三方开源库」逐项结论：

| 图形 | 候选开源库 | 结论 | 理由 |
|---|---|---|---|
| 趋势折线图 | ImPlot | ✅ **已引入** | 见 [xmake.lua](file:///Users/kench/Documents/codespace/mine/imgui/Imgui_Altitude-/xmake.lua) 第 96-98 行，已 vendor `ThirdParty/implot` |
| 开关 | imgui_toggle | ✅ **已引入** | 同上，第 91-95 行 |
| 圆形仪表盘/旋钮 | **imgui-knobs**（altschuler/imgui-knobs，MIT）| ⚠️ 可参考但**推荐自封装** | 它是「编辑型旋钮」（拖拽改值），本项目的海拔仪表是「只读进度环+大数字」，语义不匹配；但可借其 `Arc` 变体的弧线绘制与命名空间组织风格作参考。[ImGui Knobs](https://blog.gitcode.com/c4f5b8bb4fec33f9c486eeb5c2678c80.html) [ImGui-Knobs 教程](https://blog.csdn.net/gitblog_00032/article/details/141844775) |
| 分段控件 | 无成熟独立开源库 | ❌ 无开源 | 需自封装；现有 `UI::DrawSegmented` 已近乎完成，升级为独立控件即可 |
| 状态徽章（呼吸点） | 无 | ❌ 无开源 | 逻辑简单但语义明确，自封装 `StatusBadge` |
| 信息卡/统计卡 | 无 | ❌ 无开源 | 自封装 `StatCard` |
| 地形装饰图 | 真实地图库（需网络瓦片/API key）| ❌ 不建议 | 本项目移动端、离线场景，引入真实地图体积与复杂度过高；保持自封装装饰 |
| 定位针/路线折线 | — | — | 属地形图内聚内容，随地形封装或保留 |

> 依赖偏好结论：倾向「**尽量用开源替代**」，但**当前已引入的 ImPlot/imgui_toggle 已覆盖了最能开源化的部分**；剩余图形要么无成熟开源（分段/徽章/卡），要么语义不匹配（仪表）。因此**本方案不新增第三方依赖**，以「自封装语义控件」为主，这是对该项目（移动端、直接 vendor 依赖）最稳的选择。

## 四、控件封装设计方案

### 4.1 分层架构（关键）

把「控件」与「绘制原语」明确分层，避免继续用 `UI::` 大杂烩：

```
Frontend/
  UIHelpers.h/.cpp      // 仅保留纯绘制原语（非控件）：
                        //   CenteredText / DrawRoundedRect / DrawRing /
                        //   DrawGaugeArc / accentCyan
  Widgets/              // 新增：语义明确、单一用途的控件模块（仿 imgui-knobs）
    RadialGauge.h/.cpp  // 海拔仪表（圆环+进度弧+大数字+单位）
    Segmented.h/.cpp    // 分段控件
    StatusBadge.h/.cpp  // 呼吸状态徽章
    StatCard.h/.cpp     // 信息卡（标签+值+单位，可含按钮区）
```

- **控件** = 有明确 UI 语义、内部组合了绘制原语、通常返回交互结果的模块。
- **绘制原语** = 单笔画的 `AddCircle`/`AddRectFilled`/`AddText` 封装，不算控件，留在 `UIHelpers`。

### 4.2 控件 API 设计（仿 imgui-knobs 的命名空间 + 立即模式函数）

> 形态说明：imgui-knobs 用 `ImGuiKnobs::Knob("label", &val, ...)` 这种「单一命名空间 + 立即模式函数」提供明确语义的控件（[ImGui-Knobs](https://blog.csdn.net/gitblog_01195/article/details/141844730)）。我们采用同样的形态：**每个控件一个文件、一个命名空间、一个主入口函数**，调用方只关心返回值（交互结果），不暴露内部绘制细节。

**A. `Segmented`（分段控件）** — 替代 `UI::DrawSegmented` 在 NavBar / 指标切换 / 设置单位·主题的 4 处调用
```cpp
namespace Segmented {
// 返回选中索引（未点击返回 current）
int Render(const char** labels, int count, int current, float totalW, float h,
           const Segmented::Style& style = {});
}
```
- `Style` 内含 `bg/selBg/selText/idleText/gap/inset/rounding/drawBg/hover`（从现有 `SegmentedStyle` 迁来）。
- 由于「分段控件」无成熟开源库，此为自封装；现有 `DrawSegmented` 逻辑整体搬入，签名微调为带命名空间、参数收敛到 `Style` 结构。

**B. `RadialGauge`（圆形仪表）** — 封装 `renderAltitudeHero` 的「圆环+进度弧+中心大数字+单位」
```cpp
namespace RadialGauge {
// 只读式圆环进度仪表；ratio 已归一化到 [0,1]
void Render(ImVec2 center, float R, float ratio,
            const char* label, const char* value,
            const char* unit, ImU32 arcColor, float maxRange);
}
```
- 内部复用 `UI::DrawRing` / `UI::DrawGaugeArc` / `UI::CenteredText` 原语。
- 与 imgui-knobs 的区别：**只读**（无拖拽/编辑），专为本 App 的「主数字即主角」设计稿服务。

**C. `StatusBadge`（状态徽章）** — 封装 `renderStatusBadge`
```cpp
namespace StatusBadge {
void Render(const char* text, float centerX, float posY, ImU32 color, bool breathe);
}
```
- 内部含呼吸动画（`sin` 缩放圆点）与文案居中绘制，逻辑自 `RealtimeScreen` 内联代码搬入。

**D. `StatCard`（信息卡）** — 封装副信息条卡片、记录统计卡、坐标卡等「圆角矩形+标签+值+单位」结构
```cpp
namespace StatCard {
void Render(ImVec2 pos, ImVec2 size, float rounding,
            const char* label, const char* value,
            const char* unit, ImU32 valueColor);
}
```
- 替代 `RealtimeScreen::renderSecondaryInfo` 内的 `drawCard` lambda、`RecordsScreen` 统计/轨迹卡、`MapScreen::renderLocationCard` 的重复排版。

### 4.3 迁移映射表

| 现调用点 | 新控件调用 |
|---|---|
| `UI::DrawSegmented(...)`（NavBar.cpp:38 / RealtimeScreen.cpp:133 / SettingsScreen.cpp:86,98,110,150） | `Segmented::Render(...)` |
| `RealtimeScreen::renderAltitudeHero` 的圆环+弧+大数字 | `RadialGauge::Render(...)` |
| `RealtimeScreen::renderStatusBadge` | `StatusBadge::Render(...)` |
| `RealtimeScreen::renderSecondaryInfo` 的 `drawCard` lambda | `StatCard::Render(...)` |
| `RecordsScreen` 统计/轨迹卡、`MapScreen::renderLocationCard` | `StatCard::Render(...)`（按需） |
| `UI::CenteredText / DrawRoundedRect / DrawRing / DrawGaugeArc / accentCyan` | **保留不动**（纯绘制原语） |

### 4.4 工程接入（xmake.lua）

- `Frontend/Widgets/` 需加入编译：现 [xmake.lua:86](file:///Users/kench/Documents/codespace/mine/imgui/Imgui_Altitude-/xmake.lua#L86) 为 `add_files("Frontend/*.cpp|WebViewPanel.cpp", "Backend/*.cpp")`，改为追加 `"Frontend/Widgets/*.cpp"`：
  ```lua
  add_files("Frontend/*.cpp|WebViewPanel.cpp", "Frontend/Widgets/*.cpp", "Backend/*.cpp")
  ```
- 各控件 `#include "Frontend/Widgets/xxx.h"` 即可，无需新增第三方包（`add_requires` 不变）。

## 五、假设与决策

1. **不新增第三方依赖**：已用 ImPlot / imgui_toggle 覆盖了最能开源化的部分；剩余图形无成熟开源或语义不匹配。若日后确有「可编辑仪表」需求，再评估引入 imgui-knobs。
2. **控件形态 = 单一命名空间 + 立即模式函数**（仿 imgui-knobs），而非 `UI::` 大杂烩；每个控件一个文件、单一职责。
3. **`UIHelpers` 收窄为纯绘制原语层**，不承担控件职责；`accentCyan`、`DrawRing`、`DrawGaugeArc` 等原语保留。
4. **地图屏的等高线/路线/定位针**为装饰性内容，本次不接入真实地图；作为 `MapScreen` 内部实现保留（若想彻底控件化，可后续单独抽 `TerrainMap`，但不阻塞本次）。
5. 各控件保持**与现有像素观感完全一致**（颜色/间距/圆角来自现实现），迁移为纯重构，不改变视觉与交互。
