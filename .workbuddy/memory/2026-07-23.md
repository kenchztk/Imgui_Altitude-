## 字体跨平台分发与加载
- xmake after_build 分发 assets/fonts/MapleMono-NF-CN-Regular.ttf：macOS → .app/Contents/Resources/fonts/（codesign 前）；Android → android/app/src/main/assets/fonts/；Windows → 可执行文件旁 fonts/
- Frontend::initFonts 用宏区分加载：__ANDROID__ 经 AndroidGetAssetData（mainAndroid.cpp 新增包装，AAssetManager 读内存）+ AddFontFromMemoryTTF；__APPLE__ 用 CFBundleCopyResourcesDirectoryURL 解析 Resources 路径（裸二进制回退 assets/ 相对路径）；_WIN32 相对路径 fonts/
- 主字体尺寸由硬编码 18.0f 改为 size_pixels 参数（macOS 26.6px，Android 66px）；回退链：MapleMono → STHeiti(macOS) → ImGui 默认
- macosx 增加 CoreFoundation framework；两平台构建零错误

## 修复 Android 定位权限申请失败
- 根因：LocationProviderAndroid.cpp 的 callKotlinVoid/RegisterLocationNatives 中 `GetEnv != JNI_OK 即 return`，而 android_main 是未附加 JVM 的 native 线程，GetEnv 必返 JNI_EDETACHED → 直接退出，requestPermissions 从未被调用。正确模式（同 ShowSoftKeyboardInput）：仅 JNI_ERR 才失败，JNI_EDETACHED 继续 AttachCurrentThread，且只在 needDetach 时 Detach（避免误 Detach UI 线程）
- Kotlin 侧配套修复：requestLocationPermission/startLocationUpdates/stopLocationUpdates 切 runOnUiThread；requestLocationUpdates 显式传 mainLooper（native 线程无 Looper 会抛 RuntimeException）；已授权时直接回调 nativeOnPermissionResult(true) 免重复弹窗
- JNI 陷阱（项目通用）：native 线程调 JNI 前 GetEnv 返回 JNI_EDETACHED 是常态，不是错误
