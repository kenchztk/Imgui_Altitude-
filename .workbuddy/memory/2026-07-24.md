## 动态库可行性评估（会话主题）
用户想评估「把 imgui 编译成 C++ 动态库，各平台加载」的复杂度与可行性。已读 CLAUDE.md / README.md / HANDOFF.md / xmake.lua 了解项目。

- 项目：跨平台海拔高度测量应用，C++20 + xmake，Dear ImGui UI 框架，macOS(Metal/CoreLocation) + Android(GLES3/JNI) 双平台，Windows 已注释保留。
- 用户明确选择「范围 A：仅把 Dear ImGui 库本身编成动态库」（不含业务核心），并需澄清「宿主」概念。

### 关键结论
- Dear ImGui 编成动态库完全可行（源码分发 + IMGUI_API 导出宏）。
- 唯一技术难点：符号导出。xmake.lua L9 有 `add_cxflags("-fvisibility=hidden")`，编动态库须显式导出（mac/Linux 用 visibility("default")，Windows 用 __declspec）。
- Android 端本就是 set_kind("shared") 产出 .so，天然契合动态库形态。
- 范围 A 复杂度=低（纯构建配置 + 导出宏，无 ABI 边界/业务切分）。
- 范围 B（整个应用核心进动态库）复杂度=中高，需在宿主/核心间定义 extern "C" ABI，剥离 OS 循环与图形设备。

### 优化（Android 安全区 safe area，解决圆角/挖孔裁切控件）
用户反馈：无边框了，但 ImGui 不知安全区，圆角/挖孔设备控件被裁切（"超出屏幕"）。非 ImGui 硬限制，标准解法是喂入系统边距。
- MainActivity.kt：新增 `external fun nativeSetSafeAreaInsets(top,right,bottom,left)`；`pushSafeAreaInsets()` 读 `rootWindowInsets`：API29+ 取 `displayCutout.safeInset*`，API31+ 取四角 `RoundedCorner.radius` 取各边 max；`onCreate.post{}` 与 `onWindowFocusChanged`(隐藏系统栏后) 调用回传。用 `maxOf`（kotlin.comparisons 默认导入），避免 `max` 未导入编译失败。
- LocationProviderAndroid.cpp：RegisterNatives 增加 `nativeSetSafeAreaInsets "(FFFF)V"`；实现写入全局 `g_SafeTop/Right/Bottom/Left`；新增 `AndroidGetSafeInsets(...)` 供 Frontend 读取。单位 px，与 io.DisplaySize 同坐标系。
- Frontend.cpp：`update()` 内 Android 下读 AndroidGetSafeInsets，主窗口 `SetWindowPos(sLeft,sTop)` + `SetWindowSize(DisplaySize - insets)`，收敛进安全矩形；其余平台仍铺满。AltitudeDisplay 内部用 GetContentRegionAvail，自动随窗口内缩，无需改。
- 待真机校验（本机无 Android 环境）。已知风险：若 native GLES surface 缓冲分辨率与真实 px 不一致（个别厂商 render scale），insets 可能需按 DisplaySize/真实屏高 缩放。

### 修复（Android 安全区导致启动崩溃）
用户实测上一版安全区改动→启动直接崩溃退出。根因=时序崩溃：Kotlin `external fun nativeSetSafeAreaInsets` 经 `RegisterNatives` 静态绑定，而 `RegisterLocationNatives` 在 `mainAndroid.cpp:185` 的 `android_main`（native 主线程，晚于 Java onCreate）才执行。`MainActivity.onCreate` 末尾 `window.decorView.post { pushSafeAreaInsets() }` 在主线程下个消息循环即跑，几乎必然早于 native 注册 → ART 按 JNI 命名约定找不到导出符号 → UnsatisfiedLinkError 未捕获 → 崩溃。
- 修复 MainActivity.kt：① 删掉 `onCreate.post{pushSafeAreaInsets()}`（注释说明原因）；② `pushSafeAreaInsets()` 内 `nativeSetSafeAreaInsets` 调用外包 try/catch(UnsatisfiedLinkError) 兜底。安全区改由 `onWindowFocusChanged(hasFocus)` 统一回传（时机远晚于注册，必安全）。
- C++ 端（LocationProviderAndroid.cpp / Frontend.cpp）无需改。
- 待用户真机重建校验：应不再崩溃，且控件收敛进圆角安全矩形。

### 优化（Android 安全区内边距过度收缩）
用户实测上一版不崩溃了，但安全区收得太靠内、内容区过小。排查：io.DisplaySize 来自 ANativeWindow_getWidth/Height（物理像素），DisplayFramebufferScale=(1,1)，与 insets（rootWindowInsets 物理像素）单位一致，非缩放问题。根因=个别厂商 ROM 把圆角曲率半径 getRoundedCorner().radius 报得过大（可达数百 px），四边各减致内容过小。
- 修复 Frontend.cpp update()：Android 下读 AndroidGetSafeInsets 后，把每边安全区 clamp 到屏幕对应维度的 8%（kMaxInsetFrac=0.08f）。正常圆角屏(占比4~7%)不触发，异常大值压回合理范围。不改 Kotlin 端。
- 待真机校验。若仍偏大，可调小 kMaxInsetFrac，或按 [SafeArea] 日志原始值精准设定上限。

### 修复（Android 编译不通过）
用户按 `xmake f -p android -a arm64-v8a --ndk=.../ndk/27.0.12077973 --ndk_sdkver=27 && xmake` 实测编译失败，两处根因：
1. 缺 `#include <cmath>`（用了 sinf/cosf/sqrtf 但忘了包含头文件）。

- 修复后 xmake 编译通过，libNativeApp.so 已拷贝到 android/app/libs/arm64-v8a/。仅余 spdlog 弃用警告（Frontend.cpp:220 字体加载，项目原有，无关）。
- 教训：本项目 ImVec2 不能用向量 +/-，需分量运算或定义 IMGUI_DEFINE_MATH_OPERATORS。
