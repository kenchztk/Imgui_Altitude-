## UI 重设计讨论（气压海拔 App，移动端）

用户对当前界面（CircleGradient 模式，脏渐变同心圆）不满意，要求 UI 设计建议。
读取了 CLAUDE.md、Frontend/Frontend.cpp、AltitudeDisplay.{h,cpp}、StyleManager.cpp 建立认知。

给出的 3 个方向：清爽卡片式（浅色）、山形海拔仪、深色户外专业风（方案三，推荐）。

### 用户反馈（设计偏好，落实到代码时遵守）
- **不要顶部居中的「海拔高度」大标题**：与中间大数字重复且抢注意力，去掉后数字当主角，顶部只留状态点 + 模式切换条。
- 方案三（深色户外专业风，#0B0F17 背景 + #F8FAFC 文字 + #38BDF8/#4ADE80 强调）改造成本低，推荐优先实现。
- 具体改进点：模式切换从 5 个 icon 按钮改为文字分段控件；底部按钮改圆角胶囊；信息分层（一主二副 + 状态药丸 + 主按钮）；动效克制。

### 已实施（16:09 完成，macOS releasedbg 构建通过）
改了 Frontend/AltitudeDisplay.cpp 三处：
1. renderModeSwitcher：5 个 icon 按钮 → 文字分段控件（大字/仪表/刻度/卡片/圆环），用 InvisibleButton + 自绘高亮胶囊。
2. renderCircleGradient：去掉脏渐变三层圆环，改为单色淡圆环 + 海拔进度弧（270° 映射 0..maxRange，PathArcTo+PathStroke）+ 方向箭头。
3. renderControls：「详情」改为右侧小文字按钮；「开始/停止」改圆角胶囊（Idle=强调色 CTA，Running=中性色 #1E293B，FrameRounding=22）。
顶部不再有大标题（用户明确要求），海拔数字当主角。
构建：`xmake f -m releasedbg && xmake build` → 通过，仅 spdlog/fmt 第三方弃用告警（非代码问题）。

### 第二轮：补齐主界面信息展示（16:24 完成，macOS + Android 双平台构建通过）
用户指出：(a) 气压必须展示；(b) 上轮界面没严格按草图——主屏看不到气压/精度/垂直速率。
落实改动：
- **副信息条**：在 AltitudeDisplay 的 `##alt_display` 与 `##controls` 之间插入固定 `renderSecondaryInfo`（所有模式共用），两张等宽圆角卡：**气压计**(hPa) 与 **垂直速率**(m/min，爬升绿/下降橙)。render() 预留 `estimateSecondaryHeight()` 高度。
- **精度药丸**：`renderStatusBadge` 改为接收 `data`，文案追加「· 精度 ±X 米」，严格对齐方案三草图（药丸=状态+精度，卡片=气压+垂直速率）。
- **桌面端也能看到数值**（用户在 macOS 上无气压计）：
  - `AltitudeFusion::update` 的 no-pressure 分支改为用 GPS 海拔差分(EMA)估垂直速率，不再强制置 0 → 垂直速率卡在任何平台都有值。
  - `Backend::currentFused` 在无真实气压计且 GPS 有效时，按海拔反推**估算气压**写入 `pressureHPa`（hasPressure 仍 false）→ 气压卡显示「hPa 估算」；Android 有真实传感器时为真实值。
- 验证：`xmake f -p macosx -m releasedbg && xmake build` 通过并重新签名 pkg/NativeApp.app；Android 目标也通过。
- 关键约束：气压真实获取仅 Android（`PressureProviderAndroid` 走 ASensorManager）；macOS/iOS 当前 PressureProvider::Create() 返回 nullptr（iOS 未来可经 CoreMotion CMAltimeter）。

### 第三轮：修复底部按钮被挤出（16:38）
用户反馈：加了副信息条后，最底端「开始/停止」测量按钮不显示；并提到「手动调整高度」一直不展示。
- **根因**：`render()` 里 `BeginChild("##alt_display", ImVec2(0, ImMax(avail.y - h3 - h2, 50.0f)))` 的 **50px 下限**。窗口偏矮（Android 安全区 / macOS 缩窗）时 `avail.y - 底部预留` 变很小甚至为负，被 clamp 到 50 → 副信息条+控制区实际需要高度 > 剩余空间 → 底部按钮溢出不可见。
- **修复**：中间区高度下限改取 0（`middleH = ImMax(avail.y - (h2+h3+12 安全余量), 0.0f)`）。窗口矮就缩中间区，但底部「开始/停止 + 详情」一定留出来。macOS releasedbg 构建通过。
- **「手动调整高度」澄清**：全仓搜索确认代码里**没有任何手动调高控件**（UI 中无手动入口；offset 仅出现在 EGM96 偏移计算与第三方库）。需向用户确认其含义——可能是期望新增手动海拔/气压计校准输入，也可能指「详情」里的椭球高信息（底部挤出后连「详情」都点不到，布局修复后应可見）。
