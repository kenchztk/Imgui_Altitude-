## 修复：SetCursorPos 扩展父窗口边界断言（imgui-error 00215）
- 现象：点击设置按钮报 `[00215] imgui-error ... uses SetCursorPos()/SetCursorScreenPos() to extend window/parent boundaries`，发生在 `##body` 子窗口（渲染当前屏）。
- 根因：ImGui 1.92 起，窗口/子窗口**最后一次操作**若为 `SetCursorScreenPos` 且超出当前内容边界、其后未提交任何 item，则在 `EndChild()` 触发 `ErrorCheckUsingSetCursorPosToExtendParentBoundaries()` 断言。
- 受影响屏：`SettingsScreen`（末行 `staticRow` 后 `SetCursorScreenPos(cp.y+rowH+gap)`）、`RecordsScreen`（末卡后 `SetCursorScreenPos(cp.y+cardH+cardGap)`）——两者都存在，点设置/记录都会崩。`RealtimeScreen`/`MapScreen` 末尾是 Button(item)，无此问题。
- 修复：在两屏 `render` 的 `return` 前各加一句 `ImGui::Dummy(ImVec2(0.0f, 0.0f));`——既清除 IsSetPos 消除断言，又使 `##body` 内容高度正确（溢出时滚动范围正确）。已 `xmake f -m releasedbg && xmake` 重新编译打包签名通过，仅第三方 spdlog/fmt deprecation 提示（非代码问题）。
- 经验：凡用 `SetCursorScreenPos` 手工布局且窗口/子窗口末尾不跟 item 的写法，结尾都需补 `Dummy()`。

## 评估：ImDrawList 手绘控件可否用现成轮子替代
- 结论：应用层大量用 ImDrawList 手撸标准控件，且**同一控件存在 3 份重复实现**（分段控件在 NavBar / RealtimeScreen::renderMetricSwitcher / SettingsScreen::DrawSegmented 各一遍）。
- 可替代方案分级：
  - **Tier 0（零依赖，先做）**：分段控件合并为 1 个 `UI::DrawSegmented(Selectable 组合)`；新增 `BeginCard/EndCard`、`DrawGauge`、`CenteredText` 共享 helper，替换 5 处圆角卡片、圆环仪表、居中大数字。消除重复、零集成风险。
  - **Tier 1（轻量外部库）**：`cmdwtf/imgui_toggle`（header-only, 0BSD）替换 `DrawToggle`；`epezent/implot`（ImGui 同生态，2-3 cpp，零额外依赖）替换趋势折线图 `renderTrendHero`（约 5 行换 45 行，免费得交互）。implot 需 pin 兼容 ImGui 1.92.8 的版本。
  - **Tier 2（可选）**：`imgui-knobs` 仅当想要交互旋钮时引入；只读进度环保留 `DrawGauge` helper 即可。
  - **保持**：MapScreen::renderTerrain 示意性等高线/路线/定位针无合适轮子，真实地图超范围，保持原样。
- 关键集成陷阱：项目把 imgui 编成共享库 libimgui.{dylib,so}，若 implot 编入 NativeApp 必须显式 `ImPlot::SetImGuiContext(ImGui::GetCurrentContext())` 跨 DLL 共享上下文；初始化顺序 CreateContext→ImPlot::CreateContext→SetImGuiContext，放 StyleManager/Frontend::init。
- 用户尚未确认是否开工；建议先做零依赖的 Tier 0。
